# go-cmd

[![CI](https://github.com/grongor/go-cmd/actions/workflows/ci.yaml/badge.svg)](https://github.com/grongor/go-cmd/actions/workflows/ci.yaml)
[![Go Reference](https://pkg.go.dev/badge/github.com/grongor/go-cmd.svg)](https://pkg.go.dev/github.com/grongor/go-cmd)
[![Coverage Status](https://coveralls.io/repos/github/grongor/go-cmd/badge.svg)](https://coveralls.io/github/grongor/go-cmd)

`go-cmd` wraps [`os/exec`](https://pkg.go.dev/os/exec) behind small interfaces (`Factory`, `Command`, `Process`,
`ProcessState`, `ExitError`) so that code which runs external commands can be unit-tested without running them.
In production you use `cmd.NewOsExecFactory()`, which is a thin layer over `exec.Command`; in tests you inject the
[testify](https://github.com/stretchr/testify) mocks from the `mocks` package (generated by
[mockery](https://github.com/vektra/mockery)).

## Installation

```sh
go get github.com/grongor/go-cmd
```

Requires Go 1.26 or newer (the oldest Go release that is still supported).

## Usage

Depend on `cmd.Factory` instead of calling `exec.Command` directly:

```go
package git

import (
	"strings"

	"github.com/grongor/go-cmd"
)

type Git struct {
	factory cmd.Factory
}

func New(factory cmd.Factory) *Git {
	return &Git{factory: factory}
}

func (g *Git) CurrentBranch() (string, error) {
	output, err := g.factory.Command("git", "branch", "--show-current").Output()
	if err != nil {
		return "", err
	}

	return strings.TrimSpace(string(output)), nil
}

// In production: git.New(cmd.NewOsExecFactory())
```

and mock it in tests:

```go
package git_test

import (
	"testing"

	cmd_mocks "github.com/grongor/go-cmd/mocks"
	"github.com/stretchr/testify/require"

	"example.com/project/git"
)

func TestCurrentBranch(t *testing.T) {
	command := cmd_mocks.NewCommand(t)
	command.EXPECT().Output().Return([]byte("main\n"), nil)

	factory := cmd_mocks.NewFactory(t)
	factory.EXPECT().Command("git", "branch", "--show-current").Return(command)

	branch, err := git.New(factory).CurrentBranch()
	require.NoError(t, err)
	require.Equal(t, "main", branch)
}
```

The mocks assert their expectations when the test ends. Variadic arguments are matched one by one, so
`EXPECT().Command("git", "branch", mock.Anything)` matches exactly one argument after `branch`. Use
`mock.Anything` for each argument you don't care about.

## Differences from os/exec

Every wrapped method behaves exactly like its `exec.Cmd` (or `os.Process`, `os.ProcessState`) counterpart. The only
differences are in the types:

- `exec.Cmd` fields are exposed as getters and setters (`GetDir`/`SetDir`, `GetEnv`/`SetEnv`, ...; `Args`, `Env` and
  `ExtraFiles` also have `Append*` variants). The setters panic with `cmd.ErrAlreadyStarted` once the process has
  been started.
- An `*exec.ExitError` returned by `Run`, `Wait`, `Output` or `CombinedOutput` is returned as a `cmd.ExitError`, so
  check it with `var exitErr cmd.ExitError; errors.As(err, &exitErr)`. It unwraps to the original
  `*exec.ExitError`, so `errors.As(err, &execExitErr)` keeps working too. Any other error is returned unchanged.
- `exec.Cmd.Process` and `exec.Cmd.ProcessState` are returned by `GetProcess` and `GetProcessState` as `cmd.Process`
  and `cmd.ProcessState` (or `nil` if the process hasn't been started or waited for yet).

`AppendEnv` behaves like `cmd.Env = append(cmd.Env, ...)`. While `Env` is `nil` the command inherits the current
environment, so appending to a `nil` `Env` drops the inherited environment. To add variables to the inherited
environment, use `command.SetEnv(append(command.Environ(), "KEY=value"))`.

When you need something the interfaces don't cover, such as a library that takes an `*exec.Cmd`, the production
implementation exposes the wrapped command: `command.(*cmd.OsExecCommand).Cmd()`. Code that uses it can't be
tested with the mocks.

## Stopping a command

Every wrapped method behaves exactly like its `exec.Cmd` counterpart, so graceful termination uses the `exec.Cmd`
mechanism from Go 1.20: create the command with `Factory.CommandContext`, use `SetCancel` to decide what happens
when the context is done (by default the process is killed) and `SetWaitDelay` to set how long `Wait` gives the
process to exit after that before killing it. This works with `Run`, `Output`, `CombinedOutput` and `Start`/`Wait`
alike.

```go
ctx, stop := context.WithCancel(context.Background())
defer stop()

command := factory.CommandContext(ctx, "my-server")
command.SetCancel(func() error { return command.GetProcess().Signal(syscall.SIGTERM) })
command.SetWaitDelay(5 * time.Second)

go func() {
	<-shutdown
	stop() // SIGTERM now, SIGKILL if the process is still running 5s later
}()

output, err := command.Output() // e.g. "signal: terminated"
```

See the [package documentation](https://pkg.go.dev/github.com/grongor/go-cmd) for the full API and runnable
examples.
